# Общий план проекта

План отражает актуальные **исполняемые** зависимости, без повторного согласования уже принятых технических решений. Конкурсное задание получено; 01–08 и два заполненных OpenAPI существуют как проектные документы, **код и тесты ещё отсутствуют**. Единый реестр задач — [БЭКЛОГ.md](БЭКЛОГ.md). Приоритеты плановые.

| Веха | Условие входа | Результат / условие выхода | Задачи |
|---|---|---|---|
| Этап 0. Документационная основа | Документальный комплект собран | Проверить и адресно скорректировать установленные замечания; не считать работы по коду выполненными | DOC-001 |
| Актуальная предметная основа | Конкурсное задание и действующие 01–04/06 уже имеются | Работать по согласованным решениям; новые предметные вопросы уточнять только при доказанном пробеле | PRD-001, PRD-002 |
| Контрактная подготовка и исполняемые источники | 05/07/08 и два OpenAPI подготовлены | Адресно проверить договорённости и схемы; создать миграции и серверные фикстуры по ТД-01–20; без повторного выбора стека или MSW runtime | ARC-001, DATA-001, UX-001, SEC-001, API-001, API-002, MOCK-001 |
| Реализация | Существующие 05–08/YAML; разработка может начаться с вертикали auth → профиль → ACL → расписание | Серверные сессии, P-миграции, UI, адаптеры и сохранённые операции по согласованному объёму; реальный код и тесты | DEV-001–DEV-009 |
| Проверка и демонстрация | Реальный код, вымышленные фикстуры и проверяемая среда | Негативные SEC-/API-тесты, 360/390 px, URL из РФ, два аккаунта и фактический конкурсный комплект; никакой фиктивной отметки «готово» | QA-001, DEP-001, DOC-002 |

Переход к первой исполняемой вертикали **не требует** повторного утверждения закрытых решений 01/05–08. DEV-001/002/003 можно начать сразу с одновременными локальными контрактными проверками и подготовкой фикстур. Защита, тестирование, развёртывание и конкурсные доказательства остаются обязательными воротами; календарный план и факт исполнения пока не подтверждены.
