# Сценарии ответов тестовых внешних API

Это **план покрытия**, не готовые JSON-фикстуры и не работающие обработчики. Поля, статусы, коды ошибок и операции уже определены в [внешнем OpenAPI](../API/Контракты_внешних_систем.yaml) и [студенческом API](../API/Контракт_студенческого_API.yaml); фактические ответы ещё нужно построить по этим схемам и [ТД-01–ТД-20](Тестовые_данные.md). Для каждого серверного направления из [каталога](Каталог_моков.md) запланирован минимум:

| Класс ответа | Условие в будущей фикстуре | Проверяемое поведение своего сервера |
|---|---|---|
| Успех | Есть относящиеся к студенту данные | Сервер применяет права/правила и отдаёт согласованное представление |
| Ошибка внешнего источника | Тестовый API возвращает отказ/недоступность | Сервер не выдумывает данные, не теряет сохранённую операцию, показывает согласованную ошибку |
| Отсутствие данных | У источника нет записи для запроса | Сервер корректно возвращает пустое состояние без фиктивных элементов |

Дополнительные **планируемые** проверки: изменение занятия согласованно отражается в расписании и уведомлениях; две модели оценивания, официальные подгруппы и разные семестры не смешиваются; выданная работа не приравнивается к несданной при неизвестном выполнении; заявка остаётся собственной после локального commit и внешнего отказа; чужой материал скрыт; `PARTIAL`/`SOURCE_ERROR` не превращаются в подтверждённый ноль. Для операций заявок и обращений воспроизвести ACK, потерю ответа, retry с прежним `operationId`, смену `sourceRevision`, старый статус и timeout, не создавая дубликатов. Порядок доставки и задержки заданы инженерными правилами 05/08 и контрактами, но ещё не проверены кодом; исторические [ИНТ-02 и API-01](../09_Реестр_нерешённых_вопросов.md) не переоткрывают утверждённые операции.
