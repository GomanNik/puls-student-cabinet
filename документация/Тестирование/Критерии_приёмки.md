# Критерии приёмки

## Документационная основа этапа 0

| ID | Критерий | Способ проверки |
|---|---|---|
| КП-00-01 | Вся согласованная структура создана; документы непустые; нет дополнительных документов | Сверить дерево репозитория с заданием этапа 0 §3 |
| КП-00-02 | Подтверждённое, предложенное и неизвестное различаются; у существенных требований есть ID и источник | Проверить [реестр](../03_Реестр_функциональных_требований.md) и [основания](../01_Основания_и_ограничения.md) |
| КП-00-03 | Каждое действующее ФТ, НФТ и СЦ связано с предметным ожидаемым результатом и запланированной проверкой; упомянутые маршруты действительно присутствуют в заполненных контрактах | Сопоставить [матрицу](Матрица_покрытия_требований.md), [03](../03_Реестр_функциональных_требований.md), [04](../04_Пользовательские_сценарии.md) и оба YAML; не считать матрицу результатом теста |
| КП-00-04 | Два **заполненных** OpenAPI 3.1 структурно согласованы с 05–08: маршруты, `$ref`, operationId, параметры пути, auth, HTTP-ошибки, две демонстрационные формы, версии, partial/unknown, идемпотентность, календарный экспорт | Отдельно провести YAML parse, валидатор OpenAPI 3.1 (при доступности), JSON Pointer, Draft 2020-12 и положительные/отрицательные payload-тесты; после реализации — контрактные испытания обработчиков. Не считать успешный разбор YAML полной проверкой OpenAPI |
| КП-00-05 | Открытые решения собраны; найденные противоречия и ограничения аудита отражены в отчёте | Сверить [вопросы](../09_Реестр_нерешённых_вопросов.md), историю коммитов Git (если она существует) и отчёт |

## Будущий прототип

Конкурсное задание и действующие продуктовые/технические спецификации уже предоставлены. Для приёмки **после появления кода** требуется настоящая серверная логика и БД; собственный Student API и серверные вымышленные адаптеры; два изолированных аккаунта; дисциплины с разными моделями оценивания и официальными подгруппами; отдельная курсовая; собственные сохранённые заявки и обращения; occurrence-уведомления и read-all; согласованный календарь и экспорт с отказом при пустой/неполной выборке; read-only ИИ; сценарии 04 (включая СЦ-19–24 и варианты) на мобильном экране от 360 px. Детальные критерии — в [реестре](../03_Реестр_функциональных_требований.md), [матрице](Матрица_покрытия_требований.md), [плане](План_тестирования.md) и 08. **Контракты описаны; код не реализован; испытания не выполнены.**
